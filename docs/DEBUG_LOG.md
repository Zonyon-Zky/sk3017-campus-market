
# 校园拾光集 Debug 日志

> 每条记录按“现象 → 根因 → 解决 → 预防”编写。

## BUG-001 ｜ 2026-11-23 ｜ 搜索 `%` 返回全部商品
- **现象**：计划用 `LIKE CONCAT('%', keyword, '%')` 搜索时，输入 `%` 会被 MySQL 当成通配符，理论上会匹配所有商品，无法实现题目要求的特殊字符演示。
- **根因**：SQL LIKE 的 `%`、`_` 本身有通配语义，用户输入没有先转义。
- **解决**：使用 `=` 作为显式转义符：先把 `=` 替换为 `==`，再把 `%` 替换为 `=%`、`_` 替换为 `=_`，SQL 写成 `LIKE %s ESCAPE '='`。单引号仍由参数化查询处理。
- **预防**：所有模糊搜索统一走 `like_value()`；测试必须覆盖 `%`、`_`、`'` 三类输入。

## BUG-002 ｜ 2026-11-23 ｜ seed 商品状态与 ENUM 不一致
- **现象**：生成 seed 数据时把一件商品的 `off_sale` 写入 `status`，导入 MySQL 时会因 ENUM 不接受该值而失败。
- **根因**：应用状态定义是 `on_sale / sold / offline`，生成脚本使用了错误拼写。
- **解决**：统一使用 `offline`，并在 `market.py` 中用 `STATUS_LABELS` 作为唯一状态映射。
- **预防**：状态值、页面文案、SQL ENUM 三处由同一常量或同一文档约定，seed 写入前运行初始化测试。

## BUG-003 ｜ 2026-11-23 ｜ 上传失败可能留下孤立文件
- **现象**：如果一边遍历图片一边保存，第二张图片格式错误时，第一张已经写入磁盘，但商品没有创建成功。
- **根因**：文件系统写入不在数据库事务中，校验和保存顺序不当。
- **解决**：先在内存中读取并完成全部图片的格式、大小和数量校验；全部通过后才写文件。数据库插入异常时回滚并删除已保存文件。
- **预防**：文件上传按“校验全部 → 保存 → 写数据库 → 失败清理”的顺序处理；测试覆盖无图、错误格式、超大图片。

## BUG-004 ｜ 2026-11-23 ｜ 非卖家可构造回复请求
- **现象**：详情页只给卖家显示回复框，但任何登录用户都可以手工向 `/messages/<id>/reply` 发送 POST。
- **根因**：仅靠模板隐藏按钮不是权限控制，后端缺少卖家身份校验。
- **解决**：回复接口联查 messages → products，检查 `product.seller_id == session.user_id`，不匹配返回 403。
- **预防**：任何写操作后端都重新校验资源归属；页面隐藏只做体验，不作为权限边界。

## BUG-005 ｜ 2026-11-23 ｜ 自动化截图找不到“收藏商品”
- **现象**：Playwright 在未登录商品详情页查找文本“收藏商品”，等待 30 秒超时。
- **根因**：未登录时页面实际按钮是“登录后收藏”，测试脚本假设了登录状态。
- **解决**：脚本先点击“登录后收藏”，完成登录后再点击详情页收藏按钮。
- **预防**：端到端脚本按真实用户路径写选择器，不按理想状态假设；关键按钮增加稳定的语义文本或 data 属性。

## BUG-006 ｜ 2026-11-23 ｜ 整体请求限制与单图限制混用
- **现象**：只设置 Flask `MAX_CONTENT_LENGTH` 时，一次上传 3 张各 1.9MB 的图片在 7MB 总限制内，但仍必须分别确保每张不超过 2MB；只看总体限制不够。
- **根因**：总请求上限和单文件上限是两个不同约束。
- **解决**：配置 `MAX_CONTENT_LENGTH=7MB` 防止超大请求，同时每张文件读取 `MAX_IMAGE_BYTES+1` 字节后独立校验 2MB。
- **预防**：上传功能同时测试单文件超限、数量超限和总请求超限三类边界。

---

**复盘小结**：6 条记录中，2 条是输入边界（BUG-001/006），2 条是数据一致性（BUG-002/003），1 条是权限边界（BUG-004），1 条是自动化测试假设（BUG-005）。这些正是 `tdd` 的 seam 测试和 `ponytail` 的“不要省略校验、错误处理和测试”规则要提前覆盖的地方。
