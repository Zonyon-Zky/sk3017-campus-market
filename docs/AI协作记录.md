
# AI 协作记录

> 本次实际安装并阅读了两个外部 skill，然后按其约束完成校园二手交易平台。代码仓库：https://github.com/Zonyon-Zky/sk3017-campus-market

## 0. 本次选择并使用的 Skill

### 工程纪律：`mattpocock/skills` → `tdd`

选择原因：题目包含发布、上传、分页、收藏、留言、权限等多个边界。TDD skill 要求先固定公共 seam、红-绿循环、按垂直切片推进，能约束 AI 不提前堆功能和抽象。

实际应用：
- 以 Flask test client + 页面/表单作为外部 seam，不测试私有函数。
- 先写 10 个 HTTP 层测试，再实现页面和路由。
- 每次只实现测试要求的行为，不额外做后台管理、聊天或支付。

### 偷懒式资深工程师：`DietrichGebert/ponytail` → `ponytail`

选择原因：用户要求最简代码、减少 token、避免屎山。Ponytail 的核心是最小完整改动、YAGNI、只用已有依赖、信任边界校验不能省、风险逻辑保留小测试。

实际应用：
- 不引入 ORM、前端框架、Redis 或消息队列。
- 使用 PyMySQL 参数化 SQL、Jinja2 服务端渲染和少量原生 JavaScript。
- 只新增 Flask、PyMySQL、python-dotenv、pytest 四个依赖。
- 上传、权限、收藏判重等高风险边界保留校验与测试。

## 1. 选题与工程纪律

**意图**：选择校园二手交易平台，并先限制实现范围，避免 AI 乱发挥。  
**提示词**：请阅读 SK3017 题目二要求，安装并阅读 mattpocock/skills 的 tdd 和 DietrichGebert/ponytail 的 ponytail。先列出 HTTP seam 和最小功能边界，不要先写代码。  
**AI 回复摘要**：建议先固定首页、详情、发布、收藏、留言、个人中心六个 seam；按 TDD 写 HTTP 层测试；按 Ponytail 删除后台管理、支付、即时聊天等非题目要求功能。  
**我的修改/采纳**：采纳两个 skill 的核心规则，确定 10 个测试用例和 6 个主路由。

## 2. 数据库与 seed

**意图**：建立够用的数据模型并准备可视化测试数据。  
**提示词**：按题目要求设计商品、图片、收藏、留言表；只做必要字段，seed 至少包含 10 件以上商品、3 个分类和特殊搜索样例。  
**AI 回复摘要**：给出 users/categories/products/product_images/favorites/messages 六表方案，留言用 parent_id 表示卖家回复。  
**我的修改/采纳**：增加 `status` 枚举、收藏唯一约束和 seed 中 `100%`、`O'Reilly` 特殊样例；状态拼写统一为 `offline`。

## 3. TDD 红-绿：列表、搜索、分页

**意图**：先用测试固定搜索和分页行为，再写实现。  
**提示词**：为首页每页 10 条、分类筛选、关键词搜索、非法页码写 pytest；搜索需要把 `%` 和 `'` 当作普通字符。  
**AI 回复摘要**：建议用参数化查询处理单引号，用 `LIKE ... ESCAPE '='` 转义 `%` 和 `_`。  
**我的修改/采纳**：先写测试并确认当前 red；再实现 COUNT + LIMIT/OFFSET 和 `like_value()`，最终测试 green。

## 4. 发布与图片上传

**意图**：在信任边界上完整校验但保持代码短小。  
**提示词**：实现 1-3 张图片上传，JPG/PNG，单张 ≤2MB，UUID 重命名；考虑失败时不要留下孤立文件。  
**AI 回复摘要**：先读取并校验全部文件，再统一保存；使用 7MB 总请求限制和 2MB 单图限制双层校验。  
**我的修改/采纳**：按“校验全部 → 保存 → 写数据库 → 异常清理”实现；测试覆盖无图、超限、错误格式、成功发布。

## 5. 收藏、留言与权限

**意图**：覆盖完整业务闭环，并防止只隐藏按钮而没有后端权限。  
**提示词**：实现收藏判重、登录用户留言、卖家回复；非卖家构造 POST 时必须拒绝。  
**AI 回复摘要**：收藏使用唯一约束 + 先查再插；回复接口联查 products.seller_id 并返回 403。  
**我的修改/采纳**：采用该权限校验；个人中心增加“我收到的留言”汇总。

## 6. 前端与真实联调

**意图**：在最小前端复杂度下做出清晰可演示的页面。  
**提示词**：用 Jinja2 服务端渲染，原生 JavaScript 只处理图片切换、上传预览和 flash 淡出；不要引入前端框架。  
**AI 回复摘要**：建议使用统一样式变量、响应式商品网格、详情页缩略图切换和个人中心 tab。  
**我的修改/采纳**：实现 10 张运行截图，使用 Playwright 走完登录、搜索、收藏、发布、留言、回复和移动端流程，控制台错误为 0。

## 7. 报告与日志

**意图**：不改变模板，在模板基础上填写课设报告。  
**提示词**：保持 SK3017 报告模板的段落、封面和章节结构不变，只填写现有占位内容并插入架构图、ER 图和运行截图。

**我的修改/采纳**：生成 `课程设计报告.docx` 和对应 PDF；未替换模板结构，未声称存在远程仓库或远程 commit。

## 使用边界

- TDD：核心业务测试在 HTTP seam 上验证外部行为，不把测试绑在私有函数实现上。
- Ponytail：不写没人要求的功能；但上传校验、权限、错误处理和必要测试没有省略。
- 本记录不声称存在远程仓库、远程提交或教师验收结果。
